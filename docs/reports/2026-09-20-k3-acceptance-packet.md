# SoulCode 人生模拟系统 · Kimi K3 验收包

## 0. 验收前背景

本项目受吕洞宾“黄粱一梦—看见人生惯性—十重考验—回到真实生活”的叙事结构启发，目标不是做一个只输出吉凶的命理工具，而是把用户的出生画像、真实人生经历和当前选择组合成一份可以被本人校正、被现实反馈修正的人生反思系统。

发起人的原始思路分两段：第一段通过生辰八字、九宫、紫微、人类图等已有七系统能力，加上用户自己填写的家庭、求学、工作、关系、门槛事件和当前状态，生成“如果继续这样走 / 如果主动改变”的人生剧本；第二段在用户看见模式后，用十个选择场景观察其第一反应，把洞察转成 7 天行动。

产品设计还参考了成熟的婚前辅导问卷、自我叙事和心理测评流程：先结构化提问，再给反馈，让参与者看见差异、确认自己的理解，最后进入具体行动。命理与 AI 都只是来源之一，不拥有对用户人生的裁决权。

## 1. 已交付路由

| 路由 | 验收重点 |
| --- | --- |
| `/master-report` | 已有七系统报告之后出现“把报告放回真实人生”入口 |
| `/life-story` | 四步人生总结向导、草稿恢复/删除、登录前保留 |
| `/life-story/result` | 可校正总结、双路径、来源标签、7 天行动 |
| `/life-story/challenges` | 十重考验、选择、反思、暂停、自动保存、完成总结 |

| `/api/life-script/generate` | 严格 JSON、宿命化表达拦截、双路径生成 |

## 2. 建议 K3 手工验收路径

### A. 入口与人生总结

1. 打开 `/master-report`，确认现有出生信息表单仍存在。
2. 进入报告结果区域，点击“开始人生总结”。
3. 依次浏览“我的起点、我的路、我的门槛、我的此刻”。
4. 在“我的门槛”不添加事件直接继续，确认出现明确提示。
5. 添加一件测试事件，填写当前状态，勾选“反思性模拟，不是命运判决”。
6. 未登录点击生成，确认跳转登录且草稿仍保存在当前浏览器。

### B. 总结校正与双路径

1. 登录后回到 `/life-story`，确认草稿恢复。
2. 生成总结工作稿，修改一句话总览或某一条模式。
3. 确认进入双路径结果页。
4. 检查“不改变路径”和“主动改变路径”都出现。
5. 检查每条洞察能区分出生画像、用户经历、当前选择、AI 推演等来源。
6. 检查免责声明明确写出“不是命运判决”。

### C. 十重考验

1. 从结果页点击“开始十重考验”。
2. 第一关选择一个选项，输入一条简短反思，点击“暂停体验”。
3. 刷新页面，确认当前关卡和进度仍在当前浏览器。
4. 使用“上一关 / 下一关”检查返回和继续逻辑。
5. 完成十关，确认完成页出现回应倾向、7 天行动和使用边界。
6. 点击“清除并重新开始”时，确认浏览器会先询问，不能静默删除进度。

## 4. K3 重点检查的风险

- 不能把“不改变路径”渲染成注定会发生的未来。
- 不能把出生画像、AI 文本或十重考验结果写成医疗、法律、投资或心理诊断。
- AI 输出不是严格 JSON、缺字段或含宿命化表达时，必须安全失败。
- 不应把 `localStorage` 当作付费凭证；支付、订单和永久档案还没有上线。
- 健康、性、创伤、法律等敏感内容必须是用户主动填写，不能变成强制追问。
- 结果页会话过期后要给出重新填写入口，而不是显示半份结果。

## 5. 外部依赖与未完成边界

当前版本可以作为 P0/P1 原型和内测版本运行。真实收费上线仍需要产品定价、支付服务商、订单回调、退款/发票策略、服务端权益账本、隐私政策和跨设备存储。这些依赖没有被假装完成，应该作为下一阶段独立验收项。
