# 人生总结、双路径模拟与十重考验开发报告

日期：2026-09-20  
项目：SoulCode / aisoulcode.cn  
范围：P0 人生剧本闭环 + P1 十重考验体验；真实支付和服务端永久人生档案仍需要外部账号与上线配置。

## 项目由来：K3 验收前必读

这个项目不是从一个普通的“命理报告页”开始的，而是从一个更大的产品命题开始：能否把吕洞宾故事中“黄粱一梦—看见人生惯性—接受十重考验—回到真实生活”的精神结构，转化成现代人可以安全参与的人生反思系统？

项目发起人的原始构想包含两层：

1. **人生剧本阶段**：用户先提供出生信息、已有七系统画像和自己对人生经历的总结；系统把“出生配置 + 已发生事件 + 当前状态”放在一起，生成一份可校正的未来路径模拟。重点不是宣称宿命，而是让人看见：如果继续沿用旧的应对方式，生活可能如何延续；如果主动改变，又有哪些小分叉可以尝试。
2. **十重考验阶段**：用户在看见人生模式后，不停留在“被说中了”的震撼，而是进入十个选择场景，观察自己在名、欲望、关系、不确定性、失去、比较、冲突、自我怀疑、责任和日常实践中的第一反应，再把洞察带回现实行动。

产品设计还吸收了婚前辅导/关系问卷和心理测评、自我叙事工具的成熟做法：先回答关于家庭、父母、朋友、亲密关系、冲突、金钱、信仰与未来期待的问题，再由引导者反馈差异，最后转成沟通与行动。本系统因此不是只问生辰八字，而是把出生画像作为一个来源，把用户亲自写下的经历和当下选择作为更重要的校正材料。

**K3 验收时请先按这个背景理解产品**：这是一个带传统文化叙事外壳的反思与行动产品，不应按“算命准确率”单一验收；第一验收指标是用户能否说清自己的经历、发现一个可讨论的惯性，并愿意在 7 天内做一个现实行动。命理和 AI 只提供观察角度，不拥有对用户人生的裁决权。

## 一、交付结果

本次把“出生画像 → 人生经历 → 人生总结 → 双路径模拟”落成了独立功能，不改现有七系统报告流式协议。

用户现在可以：

1. 从人生总览报告页进入“把报告放回真实人生”。
2. 通过四步向导填写起点、人生道路、关键门槛和当前状态。
3. 在当前浏览器自动保存、恢复或删除草稿。
4. 登录前保留草稿，登录后回到 `/life-story` 继续填写。
5. 先拿到一份可编辑的人生总结工作稿，确认后再生成模拟。
6. 查看“不改变路径”和“主动改变路径”两张路径卡，每张包含信号、风险、机会和行动；主动改变路径至少给出 3 条 7 天内可以开始的小行动。
7. 在结果页看到“出生画像、用户经历、当前选择、AI 推演”来源标签与免责声明。
8. 从双路径结果页进入 P1“十重考验”，完成十个可暂停的选择场景，并获得自己的回应倾向与 7 天行动建议。

## 三、数据与隐私边界

- 草稿 key：`life_story_draft_v1`，仅保存在当前浏览器 `localStorage`。
- 结果 key：`life_script_result_v1`，仅保存在当前浏览器 `sessionStorage`，关闭/清理会话后结果可能消失。
- 十重考验进度 key：`life_story_challenges_v1`，仅保存在当前浏览器 `localStorage`，可由用户在完成页确认后清除。
- 服务端不把完整人生经历写入日志；新路由没有原始请求日志。
- 接口限制：关键事件最多 8 条；年份范围为 1900 年至明年；不同文本字段有长度上限；无法通过校验时不调用 AI。
- AI 返回不是严格 JSON、缺少字段、主动改变路径少于 3 条行动，或包含“注定、必然、命中、一定会、不可避免”等宿命化表达时，服务端拒绝展示结果。
- 用户必须主动勾选“反思性模拟，不是命运判决”。健康、法律、投资、性暴力等敏感事项没有被设计成必答追问，也不作诊断。

## 四、接口契约

### `POST /api/life-script/summary`

请求：

```json
{
  "birthProfile": {},
  "lifeStory": { "version": 1, "origin": {}, "lifePath": {}, "events": [], "present": {}, "consent": {} }
}
```

成功返回 `{ "ok": true, "summary": ... }`；失败返回 `{ "ok": false, "errors": [...] }` 和 400。该接口是确定性的，便于用户先修改总结，也便于无 AI key 的测试环境运行。

### `POST /api/life-script/generate`

请求包含已校正的 `lifeStory` 与 `confirmedSummary`，以及可选的已有出生画像。接口复用项目现有 `generateModule` 配置，返回 `{ "ok": true, "result": ... }`。AI 服务不可用返回 503；AI 输出无法安全解析返回 502；响应带 `Cache-Control: no-store`。

## 六、商业化与后续工作

当前可落地的收费分层建议：

- 免费：人生总结向导、确定性总结工作稿、少量十重考验体验。
- 单次报告：完整七系统出生画像 + 双路径人生剧本 + 完整十重考验总结 + 可下载报告。
- 深度陪伴：人工教练/导师解读、7 天或 21 天复盘、伴侣/家庭共同版本。
- 订阅：年度人生复盘、每月新场景、行动记录和跨设备历史。

真正接入收费前仍需要明确价格、支付服务商、订单回调、退款、发票/合规和服务端权益账本；本次没有伪造支付成功，也没有把浏览器 localStorage 当成付费凭证。

## 七、暂未交付的内容

以下内容刻意留在 P1/P2，避免在没有真实用户反馈前把产品做重：

- 十重考验的游戏化关卡、积分和连续挑战。
- 真实支付、订阅、订单账本和完整报告分层售卖。
- 伴侣/家庭共同填写与教父教母式辅导工作台。
- Supabase 永久保存人生档案、跨设备同步和人工咨询记录。
- 用匿名用户数据验证“剧本准确率”的实验体系。

下一阶段建议先做 10–20 名内测用户的可用性访谈，重点记录：哪一题最难填写、总结是否被认为准确、两条路径是否促成了真实行动，再决定十重考验和收费层级。

## 八、回滚方式

若需要撤回本功能，删除人生总结相关新增目录与文件，并移除 `src/app/master-report/page.tsx` 中新增的 CTA 区块即可；现有 `/api/master-report/stream` 协议和七系统报告数据无需回滚。
