# 九宫 v6 API 收编与产品升级设计

日期：2026-07-29  
状态：已获普光师兄批准  
依据：

- `jianji-ops/decisions/2026-07-29-批准九宫v6收编API.md`
- `jianji-ops/decisions/2026-07-29-九宫v6API设计批准.md`
- `九宫姓名学-人生趋势报告-升级蓝本.html`

## 1. 目标

将现有浏览器端九宫 v6 引擎收编为站内无状态 API，并以该 API 为唯一计算入口；同时吸收升级蓝本的产品结构与交互，不吸收蓝本的精简字典、自研五格算法或任何计算逻辑。

产品升级包含：

1. 特质分析、经营环境、经营分析三个 Tab。
2. 可选择分析年份，环境信息实时联动。
3. 工作事业、财运、感情、房子、健康五类事务问询。
4. 问询动态读取所选年份的气场、碰撞、岁值星及所在九年运组。
5. 使用蓝本 27 条策略文案库。
6. 保留适合打印和导出 PDF 的样式。

## 2. 不可突破的边界

1. 现有 v6 算法只搬迁，不重写、不优化公式、不改变字段含义。
2. 王献科金标必须保持总笔画 33、局差 0。
3. `献→獻` 的 S2T 路径必须保持 13 画转 20 画。
4. 姓名和生日不落库、不写日志，接口无状态。
5. 前端不得保留 `calcFull`、康熙字库或第二条计算路径。
6. 不修改 `.env`，不自行部署；部署只经 Hermes。

## 3. 方案选择

采用站内单轨 API：

- 服务端模块持有 v6 算法、S2T 映射、康熙字库及九宫解读数据。
- `POST /api/jiugong/v6` 是唯一计算入口。
- 浏览器只提交输入、接收结果和渲染交互。

不采用独立微服务，因为它会增加部署与运维面；不采用 API 与浏览器双轨，因为它违反单一金标入口。

## 4. 架构与模块边界

### 4.1 服务端引擎

现有 `src/lib/jiugong-v3.ts` 的算法代码按原有执行顺序迁入服务端专用模块。康熙字库由服务端加载并缓存为只读数据；缓存只含公开字典资产，不含用户输入或计算结果。

服务端引擎提供单一函数：

```ts
calculateJiugongV6(input: {
  name: string;
  year: number;
  month: number;
  day: number;
}): JiugongFull
```

函数无外部副作用，不访问数据库，不产生业务日志。

### 4.2 API

`POST /api/jiugong/v6` 请求体：

```json
{
  "name": "王献科",
  "year": 1973,
  "month": 6,
  "day": 5
}
```

校验规则：

- 姓名去除首尾空白后为 2–4 个汉字。
- 年份范围为 1900–2100。
- 月份为 1–12。
- 日期必须真实存在。

成功返回：

```json
{
  "success": true,
  "engine": "jiugong-v6",
  "data": {}
}
```

失败只返回通用中文错误，不回显原始姓名和生日。实现中禁止记录请求体；捕获异常时只返回固定错误，不把可能含输入的异常内容写入日志。

### 4.3 前端输入页

输入页移除对 `calcFull` 和字库加载函数的导入，提交时仅请求 `/api/jiugong/v6`。请求期间显示计算状态；校验失败、接口失败或网络失败时显示可恢复错误，不生成本地替代结果。

隐私文案更新为：姓名与生日仅用于本次排盘计算，不作存储，不用于其他用途。不得再宣称“仅在浏览器本地计算”。

计算成功后，结果仅保存在当前浏览器会话中，用于跳转结果页；关闭会话后不持久保留。

### 4.4 结果页

结果页采用三个互斥 Tab：

- 特质分析：展示 v6 返回的格局、质数、星运、管理 IQ、五行、财富、婚姻等先天信息。
- 经营环境：选择分析年份，展示该年的四格气场、能量、岁值星、碰撞状态、年度策略和 90 年运势卷轴。
- 经营分析：提供工作事业、财运、感情、房子、健康五类问询。

年份切换只在 v6 返回的完整 90 年结果中选择对应年份及运组，不复刻蓝本计算公式。若选择年份超出返回范围，界面明确提示无可用数据，不自行推算。

五类问询是确定性文案组合，不调用 LLM。每次回答读取：

1. 当前选择年份对应的岁值星。
2. 上层、自我、下层和对外气场。
3. 对应碰撞状态。
4. 当前九年运组。
5. 与事务类别匹配的 27 条策略文案。

切换年份后，已选事务的回答立即刷新，确保环境与建议不脱节。

### 4.5 打印

打印时隐藏输入控件、Tab 按钮和交互按钮，按特质、环境、经营分析的顺序展开完整内容。屏幕端维持 SoulCode 现有视觉体系，不照搬蓝本配色。

## 5. 客户端单轨清理

完成迁移后：

1. 客户端组件不再导入服务端引擎。
2. 浏览器不再请求 `/data/kangxi-strokes.json`。
3. 客户端构建产物中不应包含 `calcFull`、S2T 大表或康熙全字库。
4. 删除旧客户端计算入口；不得以回退、兼容或隐藏代码名义保留。
5. 允许服务端保留同名类型，但必须通过 server-only 边界阻止客户端引用。

## 6. 测试与验收

### 6.1 搬迁前基准

在删除旧浏览器引擎前，用现有 `calcFull` 固化四组输入的完整输出：

- 王献科 / 1973-06-05。
- 三个额外常用姓名，覆盖两字名、三字名及另一条简繁映射路径。

基准只进入本地测试夹具；涉及真实家庭姓名的数据不写入报告。对外验收表只写 K3 指定金标和匿名化样本标签。

### 6.2 自动测试

测试按 TDD 推进：

1. API 输入校验和无效日期。
2. 王献科总笔画 33、局差 0。
3. `献→獻` 笔画路径。
4. 四组旧版与服务端版完整结果深度相等。
5. 年份切换选择正确的流年、碰撞和九年运组。
6. 五类问询随年份变化并包含规定上下文。
7. 客户端源码不存在 `calcFull` 或字库加载引用。

### 6.3 构建与人工验收

提交前执行：

- 完整自动测试。
- ESLint。
- Next.js 生产构建。
- 检查客户端构建产物不含 v6 算法特征和康熙字库。
- 本地浏览器网络检查，确认只请求 `/api/jiugong/v6`。
- 打印预览检查。

Hermes 部署后执行页面与 API 冒烟；K3 终审：

1. 金标三人或批准样本的旧版/API 逐字段比对表。
2. 网络面板确认字库不再下发。
3. 五入口回归。
4. 隐私与单轨清理复核。

## 7. 交付边界

Codex 交付代码、测试、验证证据和待部署报告，不接触服务器。Hermes 负责部署与线上冒烟，K3 负责终审。
