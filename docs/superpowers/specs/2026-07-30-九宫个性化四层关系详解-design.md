# 九宫个性化四层关系详解设计

## 1. 背景与问题

现有九宫报告的五类年度问询（工作事业、财运、感情、房子、健康）各有不同开头，但结尾统一拼接上层、自我、下层策略与碰撞提示。该段只依据所选年份的气场模板生成，没有充分结合姓名排盘产生的个人结构字段，因此不同测评人可能获得相同或高度相似的后半段解释；现有输出也缺少对外关系。

本次调整不重构现有网页布局与三 Tab 信息架构，只在现有模块内增加足够完整、可追溯、可独立阅读的内容。最终报告交付给测评人后，应无需专人二次解释即可理解术语、个人特点、年度环境、风险边界和行动建议。

## 2. 决策与边界

### 2.1 不调用生成式 AI

本功能采用确定性规则生成，不调用生成式 AI。原因是生成式模型无法保证零幻觉，不能满足“不得一本正经胡说”的质量底线。

所有分析只能来自：

1. 线上九宫 v6 API 返回的个人排盘与流年字段；
2. 本机 `LifeOS/20-29 工作事业/24.01 灵魂解码运营/九宫人生解码/` 资料包内列示文件的基本内容；
3. 经整理、校验并标注来源的确定性规则库。

没有资料依据的组合不得推断。规则缺失时输出克制的边界文案，不能使用模糊玄断补位。

### 2.2 保持现有网页结构

保留：

- 特质分析；
- 经营环境；
- 经营分析；
- 年份选择；
- 五类年度问询；
- 90 年运势卷轴；
- 现有视觉体系和主要交互。

本次不新增 Tab，不重排主要导航，不引入聊天式交互。

## 3. 资料依据工程

在编写业务规则前，对“九宫人生解码”资料包进行完整清点，覆盖：

- 九宫姓名学各章节文档；
- 五格、姓名人格、五行、属相、星运、机运、气运、特质、管理等名字解读资料；
- 婚姻、财运、人生气场、三大关系、流年、碰撞资料；
- 人生大限与能量推演表格；
- 课程讲义、课程要点、趋势密码及录音笔记；
- 课程 PPT 图片；
- 录音资料；
- 技术规格和既有验收文档。

形成内部“依据矩阵”，每条规则至少记录：

| 字段 | 含义 |
|---|---|
| sourceId | 来源文件及位置 |
| concept | 九宫概念 |
| conditions | 适用字段与条件 |
| interpretation | 资料支持的解释 |
| action | 可执行建议 |
| caution | 禁忌、边界或碰撞条件 |
| confidence | 资料明确程度 |

资料中的相同概念如存在冲突，以已批准裁决、v6 技术规格和 K3 验收口径为优先；无法裁决的内容不进入产品规则。

## 4. 内容设计

### 4.1 经营环境：个人年度四层关系详解

在现有“经营环境”内保留年份概览、四格气场卡片和 90 年运势卷轴，并扩充“个人年度四层关系详解”。

四层分别为：

1. 上层关系：与领导、长辈、制度、平台、资源支持者之间的年度互动。
2. 自我关系：个人心态、决策、节奏、能力发挥和内在风险。
3. 下层关系：与团队、属下、执行者、晚辈及承接系统之间的年度互动。
4. 对外关系：与客户、合作方、市场、公众、陌生资源和外部机会之间的年度互动。

每一层必须包含六段信息：

1. **这是什么**：用白话解释该层关系代表什么。
2. **你今年遇到什么环境**：列明所选年份的气场、能量及其资料含义。
3. **为什么你会这样承接**：引用与该层有明确资料关系的个人结构字段，解释个人特点如何放大、缓冲或改变当年环境。
4. **有利表现**：列出适合发挥的方式和可观察信号。
5. **风险表现**：列出容易误用的方式、碰撞期影响和预警信号。
6. **可执行策略**：给出具体行动、沟通、节奏、复核和止损建议。

分析不能只更换姓名或字段标签。个人差异必须进入因果解释和行动建议。

### 4.2 个性化字段组合原则

四层分析不是把所有个人字段机械堆入每张卡片，而是依据资料矩阵选择有明确关系的字段。候选字段包括：

- 天格、人格、地格、总格及五行；
- 局差、质、星运；
- 思想功能与行动功能；
- 主功能／副功能；
- 管理风格；
- 财富通路与财库；
- 关系底色；
- 岁值星；
- 九年运组、气场、能量、卦象、口诀和解读；
- 上层、自我、下层碰撞周期。

只有资料明确支持的字段关系才允许组合。每层至少使用：

- 该层年度气场和能量；
- 一项个人基础结构；
- 一项个人功能或行为结构；
- 碰撞状态或岁值星／运组信息。

“对外关系”没有独立碰撞周期时，不伪造碰撞结论；只使用总格、对外气场能量及资料明确支持的个人字段进行解释。

### 4.3 经营分析：五类年度问询

五类问询继续留在“经营分析”，分别回答工作事业、财运、感情、房子、健康。

调整规则：

1. 删除每个问询尾部重复的上层／自我／下层策略与统一碰撞句。
2. 每类问询只保留与该主题直接相关的个人化内容。
3. 每份回答包含：个人底盘、当年影响、机会、风险、行动清单、边界提醒。
4. 四层关系的完整解释只在“经营环境”出现，避免跨模块重复。
5. 健康内容明确为生活观察建议，不作诊断，不替代医疗意见。

## 5. 数据流与模块边界

新增一个纯确定性分析模块，职责单一：

```text
线上 v6 JiugongFull
        +
所选 YearEnvironment
        +
资料依据规则库
        ↓
PersonalizedRelationshipAnalysis
  - upper
  - self
  - lower
  - outer
```

每层输出结构化字段，而不是一整段不可测试的字符串：

```ts
interface RelationshipDetail {
  key: 'upper' | 'self' | 'lower' | 'outer';
  title: string;
  meaning: string;
  annualContext: string;
  personalFit: string;
  strengths: string[];
  risks: string[];
  actions: string[];
  sourceIds: string[];
}
```

页面只负责渲染；规则模块负责选择资料、组合字段和生成确定性文案；v6 引擎保持不变。

## 6. 可理解性标准

报告必须满足“无老师阅读”标准：

1. 首次出现的九宫术语紧邻白话解释。
2. 先说结论，再解释依据，最后给行动方法。
3. 不只写“宜／忌”，要说明为什么、怎么做、何时复核。
4. 不使用空泛句，如“顺势而为”“把握机会”，除非紧随具体条件和动作。
5. 每张关系卡可独立阅读，不要求读者跨页寻找前置定义。
6. 避免宿命化表达，明确趋势是观察与经营参考。
7. 内容尽可能完整，但通过小标题、列表和层级控制阅读负担。

## 7. 测试与验收

### 7.1 资料覆盖

- 资料包全部列示文件进入清点表。
- 可提取文档、表格、图片和录音均有处理状态。
- 每条上线规则至少有一个可追溯来源。
- 冲突或不明规则不进入产品。

### 7.2 确定性与个性化

- 同一姓名、生日、年份重复计算结果完全一致。
- 同一人切换年份，四层年度环境和建议随 v6 流年字段变化。
- 同一年不同个人结构的样本，四层 `personalFit`、风险或行动建议存在实质差异。
- 不允许只替换姓名、年份或字段名称后主体文案仍完全相同。

### 7.3 基准样本

至少覆盖：

- 王献科，1982-01-27；
- 两字姓名样本；
- 三字姓名样本；
- 复姓四字姓名样本；
- 有碰撞与无碰撞年份；
- 资料规则缺失的边界样本。

### 7.4 页面验收

- 经营环境显示上层、自我、下层、对外四层详解。
- 年份切换后四层内容同步更新。
- 五类问询不再重复四层策略尾注。
- 现有三 Tab、90 年卷轴、问询入口和打印结构不退化。
- 移动端、桌面端与打印版均可完整阅读。

## 8. 非目标

- 不修改 v6 计算算法和康熙字库；
- 不新增用户数据存储；
- 不调用生成式 AI；
- 不提供医疗、投资或宿命式保证；
- 不重做现有网页视觉结构；
- 不把无法追溯的资料推断写入报告。
